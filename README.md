Software Design Document, Gaming Room Project, and Reflection

Briefly summarize The Gaming Room client and their software requirements. Who was the client? What type of software did they want you to design?
What did you do particularly well in developing this documentation?

The Gaming Room was the client, and since they wanted a software system that could manage multiple game instances while making sure that each of the games and team had differences. The main goal was to design a scalable application that could handle multiple users and sessions efficiently. I think I did well when it came to clearly organizing the requirements and translating them into a design, especially when it came to breaking down system components and explaining how they would interact.

What about the process of working through a design document did you find helpful when developing the code?

So, working through the design document helped me better encapsulate the structure of the program before actually writing any of its code. It allowed me to plan out the classes, relationships, and behavior (making the coding process more organized). Having that as a blueprint made it fairly easy to avoid mistakes which reduces the need for major/expensive changes later on.

If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

If I could choose a part of my work to revise, I would say the level of detail in my design documentation can be improved, especially in the class diagrams/system explanations. While the design works well, still, I think adding more clarity and examples would make it easier for others to understand how each component actually interacts.

How did you interpret the user’s needs and implement them into your software design? Why is it so important to consider the user’s needs when designing?

I interpreted the user’s needs by focusing on the requirements given by the client, this seemed like the most logical way; such as managing multiple game sessions or ensuring unique identifiers for each entity. Considering the user’s needs is xtremely important since it ensures the software actually solved the intended problem and hit its target experience. 

How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?

I approached designing my software by breaking the problem down into smaller chunks so I could focus on the object-oriented design principles. I used techniques like class diagrams and structured planning to organize how different components would intertwine together. Going forward, I would continue using these strategies while also incorporating more details.
